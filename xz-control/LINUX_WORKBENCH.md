# Linux XZ 电机与磁数据工作台

原控制台与 `windows_acquire.py` 保留。新入口是 `linux_workbench.py` / `python -m xz_workbench`，使用现有 requirements.txt 的 PySide6-Essentials 6.8.3 和 pyserial 3.5，Python 3.10 或更新版本。

界面采用深色主题。“手动控制”和“动作函数”分为两个页签；设备连接、运动参数、更多坐标操作和采集设置按需打开。操作日志默认隐藏，可勾选显示。

## 启动

```bash
cd /home/serein/classify-cloth/xz-control
./start_linux_workbench.sh
```

首次缺少虚拟环境或依赖时启动器会创建 .venv 并安装现有依赖。Ubuntu 若缺少 venv，可安装 `python3-venv`。已有环境也可直接运行：

```bash
.venv/bin/python linux_workbench.py
.venv/bin/python linux_workbench.py --demo
```

`--demo` 只连接模拟设备，不打开实物串口；仍需人工设零和使能。模拟记录的 metadata.json 标明 demo，不能作为实验数据。

真实电机应烧录配套 XZ_Controller 1.4.0（XZ1、可调加速度、连续点动和 numeric_ranges）。程序会实际检查握手；启动不会自动设零、使能或运动，不会自动上传固件。

## 串口

选择电机和传感器两个不同串口，也可在输入框输入 `/dev/serial/by-id/...` 稳定路径。连接电机使用 115200，传感器波特率在界面选择。程序检查同一设备的路径别名；请关闭 Arduino 串口监视器等占用程序。

Ubuntu 串口报 Permission denied 时先用 `ls -l /dev/ttyACM0`（替换实际设备）核对所属组。通常可执行 `sudo usermod -aG dialout "$USER"` 后注销并重新登录。无需以 root 启动工作台。

## 第一次使用

1. 在“设备连接”选择并连接设备，在顶部“运动参数”核对 X/Z 脉冲/mm 与 X 向右符号。250 脉冲/mm 来自旧脚本，必须与实物配置核对。
2. 在手动页打开“人工标定 / 固定采集起点…”，人工对准现实中的固定基准后点击“已对准基准 · 确认机械原点”，再点击“使能运动”。需要电动对位时，先建立临时对位坐标并手动使能/点动，对准后再确认机械原点。
3. 用低速短程核对方向、距离及制动距离，再执行更大动作。Z 负向上、正向下。

位置来自发脉冲的软件计数，不是编码器实测。设零不寻找原点开关。重新连接/中途停止后如果零点失效，需要重新确认并设零，不自动恢复动作。

## 手动运动

- X/Z 分别设置速度 mm/s、加速度 mm/s²；“应用参数”提交。运动中不改变当前动作参数。
- 手动页勾选“启用方向键控制移动”（默认关闭）后，左右控制 X，上下控制 Z；按住移动，松开减速停止。须先设零、使能，并等待自动动作/校准结束。
- 方向键移动仅在“手动控制”页的主窗口处于前台时生效；切换到动作函数页、打开设置窗口、切走应用或关闭开关，都会结束当前键盘点动。其他页面和设置窗口的方向键正常编辑或导航，不驱动电机。
- 启用后的手动页内，输入框聚焦也不会用方向键修改数值。键盘自动重复不会重新发起动作；鼠标控制不受此开关影响。
- 鼠标“连续”模式同样按住移动；“定距”模式点击一次移动所设距离。键盘方向键始终连续点动。
- 一次只接受一个方向。第二个方向不会叠加，也不会在第一方向松开后自动接续，须重新按下。
- 在“更多坐标操作”可执行所选轴绝对坐标定位、X 回零或 Z 回零；另一轴保持当前位置。
- 录制/运动/函数执行期间不能设零；软件零点改变会清空当前工作坐标的软件边界，需重新配置和检查路径。

参数会换算至整数脉冲，实际行程有最多约半个脉冲的四舍五入误差；非零动作若换算为 0 脉冲会被拒绝。UI 软件边界只是附加保护，未配置时没有机械行程保护。

## 编辑动作函数

1. 新建并命名流程，点击“添加”。
2. 每行选择相对移动、绝对定位、回零、等待、重启采集板或采集空载基线。选择 X/Z；相对移动用方向和正距离，绝对定位直接填写带符号坐标。
3. 速度/加速度显示“全局”时继承左侧设置，也可给每行单独填写。等待行只使用时间秒数；重启行的时间是等待启动与新数据的超时（0 为默认 10 秒，最多 60 秒），基线行的时间是空载静止采样时长（0 为默认 2 秒，最多 600 秒）。
4. 可复制、删除、上移、下移或取消某行“启用”。
5. 点击“检查路径”查看每步起终点、脉冲位置和理想用时；检查不能证明机械不碰撞。
6. “保存”输出版本化 JSON；“加载”复用。配置不一致时必须核对并点击“采用当前配置”，再检查路径或重新保存。
7. 点击“运行函数”，或完成传感器校准后点击“运行并采集”。

各步骤串行执行，到位确认后再进入下一步。程序不按预计时间强行推进。单步 MOVE 的最大等待上限为 600 秒，预计动作过长会拒绝启动。第一版没有暂停/继续、循环、分支或任意代码执行。

函数完成后保持最后一步的位置；希望回零就自己添加指定轴回零。X 回零不同于返回函数起始 X 位置。流程加载不恢复旧零点，绝对目标使用本次人工确认的固定机械原点；未确认时禁止自动流程和绝对定位。

## 磁数据采集

传感器输入为原始四列 CSV：`t_us,Bx_uT,By_uT,Bz_uT`，单位按传感器固件为 µT。不是原始 B 的 ΔB 输入不能直接作为原始磁场接入本采集器。

连接传感器并确保数据持续更新，在“采集设置”中、静止空载状态点击“采集空载基线 · 2 秒”。至少需要 20 个有效样本；程序不会自动移动机构寻找空载。实时数值和曲线均只显示 ΔBx、ΔBy、ΔBz；未校准时显示待校准，不显示原始 B 冒充差分。新校准会清空旧曲线。保存仍同时保留原始 B 和 ΔB。

- “开始采集 / 结束保存”自行决定记录边界，可包含静止、点动、定距和普通函数运行。
- “运行函数”不改变已存在的手动录制边界。
- “运行并采集”创建独立记录；普通运动开头会等待新样本再执行，自带重启/基线时先执行准备动作，函数完成或中止后结束保存。
- “结束保存”只结束手动录制，不主动停止电机；“停止全部”同时中止运动与活动录制。
- 录制中的传感器断流、控制器异常或写盘失败会中止运动并尽力保留已有记录。

在磁数据区域输入布料名称，如“棉布”，旁边预览下一次文件名。默认保存为：

```text
data/experiments_linux/棉布_001/
  棉布_001.csv
  metadata.json
```

每个布料名称采用当前目录内最小的可用正序号；已有文件不会覆盖。移入回收站或重命名释放的空缺编号可复用，例如删除 A_002 后，下一次可再次使用 A_002。编号不代表采集时间顺序，列表按采集时间显示。名称只写入文件名和 metadata，CSV 列保持不变。上次成功创建记录或重命名使用的名称会保存到 `~/.config/xz-workbench/settings.json`，下次启动沿用。可以在采集设置选择其他保存目录；各目录独立分配编号，关闭重开沿用上次选择的目录。

“采集设置 → 管理记录”列出当前保存目录内的记录，可为旧时间戳目录 / sensor.csv 添加布料名称，或修改已有名称。新名称采用该名称的下一个编号，文件夹、CSV 文件名、metadata 标签一起更新；CSV 字节不变。仅能修改已完成或已中止并且写盘完成的记录；正在采集、后台保存或未正常结束的记录会被拒绝。旧记录不会自动改名。

辅助 metadata.json 保存 label、run_name、sequence、基线、配置、流程和完成/中止原因。编号分配以实际目录占用为准，并使用目录锁防止冲突；旧计数文件会兼容保留。

CSV 使用 UTF-8 BOM；以下 23 列与 windows_acquire.py 的列顺序、名称和含义一致：

```text
seq,sensor_t_us,device_time_unwrapped_us,device_clock_segment,sensor_t_s,host_rx_ns,host_elapsed_s,stage,motor_x_pulses,motor_z_pulses,motor_target_x_pulses,motor_target_z_pulses,motor_busy,motor_phase,motor_fault,Bx_uT,By_uT,Bz_uT,dBx_uT,dBy_uT,dBz_uT,sample_valid,invalid_reason
```

`stage` 值改为实际工作台状态或稳定动作编号 step_001 等；不是旧四段流程的固定枚举。dB=B-B0，尖峰标记不删除原始样本，格式错误的行计数。设备时间可能回绕或复位，复位时用 device_clock_segment 区分；不能跨时钟分段直接当连续时间。

CSV 分批写盘，尾部最多等待一帧确认尖峰。主机时间是串口接收时间，motor 字段是最近的控制器软件状态；两路串口没有硬件同步。正常中止保留文件，强制杀进程或断电不能保证尾部数据落盘；初始 metadata 的 interrupted 状态用于识别未正常结束。

## 函数中的采集板重启与基线

“重启采集板”只向磁传感器串口发送 `REBOOT\n`，不会重启电机控制器。等待采集板重启期间电机心跳继续；采集板可临时断开 USB，程序按设备序列号重连（设备无序列号时只重试原路径，不猜选其他串口）。

采集板固件须支持 REBOOT，并输出启动信息和 READY；当前 `fixed90` 固件的“reboot requested”及启动信息可被识别。程序必须收到重启回应/新启动信息或确认 USB 断开后的 READY，以及后续有效数据，才认为成功。一直发送旧数据的板不会被误判为重启完成；超时会中止剩余函数，不自动上传固件。

本项目附带按用户原源码制作的 C3 重启版：`firmware/mlx_c3_monitor/mlx_c3_monitor.ino`，配套 `serial_commands.h`。目标板为源码标注的 `XIAO_ESP32C3`，保留原来的引脚探测（含 GPIO3/GPIO4）、传感器设置和四列输出，仅新增重启命令与版本日志。原始 `/home/serein/classify-cloth/mlx_c3_monitor.ino` 保留用于对比。编译/使用见同目录 README；板上的旧固件需单独烧录更新，电脑上的源文件不会自动更新板子。

如果提示重启超时，打开“显示操作日志”：脚本会记录所选传感器串口/波特率、REBOOT 确认、启动信息、READY、USB 断开/重连。超时文字包含当前等待阶段、接收字节数、最后一条设备诊断和重连错误。

- 未收到 REBOOT 确认/启动信息，但仍有四列数据：优先核对板上固件是否实现命令，以及回应格式是否兼容；普通采集正常不代表固件支持重启命令。
- 已收到确认或启动信息，但缺少 READY：检查重启后传感器初始化，提示会保留 `init failed` 等设备消息。
- 已收到 READY，但没有有效磁数据：检查传感器读数和四列输出格式。
- USB 断开后未重连：查看原设备是否重新枚举、端口权限或串口占用错误。

发送 REBOOT 不依赖识别精确开发板型号，USB 序列号只用于重连同一设备。仓库中有支持 REBOOT 的源码不能证明它已经烧录到当前采集板；烧录前应另行核对实际板型与接线。

重启立即使旧基线失效。使用“运行并采集”时，后续移动前必须添加“采集空载基线”，否则在执行前拒绝运行。例如：

| 顺序 | 动作 | 设置示例 |
| --- | --- | --- |
| 1 | 重启采集板 | 超时 10 秒 |
| 2 | 采集空载基线 | 静止空载 2 秒 |
| 3 | 相对移动 Z | 到接触位置 |
| 4 | 相对移动 X | 扫描距离与速度 |
| 5 | 相对移动 Z | 抬起 |
| 6 | X 回零 | 回到工作零点 |

执行基线动作前必须自行确保传感器处于空载。基线动作不会自动抬起、调零或移动机构。

首步为重启/基线时，校准完成前不创建空 CSV。采集过程中重启或重新校准，会先保存上一段，获得新基线后再创建下一编号文件；每份 CSV 只有一个固定基线。metadata 中相同的 `context.capture_session` 标明同次采集，`segment` 为分段顺序。自动函数结束则结束采集，手动开始的采集可继续；若最后一步只重启、不再校准，不会创建没有基线的新文件。

“停止全部”在重启/校准期间同样有效，会取消后续动作和自动恢复采集。已完成保存的分段会保留。

## 停止与硬件边界

空格或“停止全部”使用固件 STOP，撤销后续动作且取消软件使能；需要检查参考是否失效。松键使用 JEND 减速停止，有制动距离。切换窗口只结束手动点动，已主动启动的自动函数继续运行；关闭工作台会中止函数。

现有硬件控制没有接入机械限位/原点搜索、硬件急停和编码器位置反馈。软件 STOP 不切断动力，也不提供 Z 轴防下滑保护。按实际机械行程、负载和接口配置使用。

## 批量运行并采集（2026-11-14）

在“动作函数”页编辑好当前函数，设置“批量次数”和“轮次间隔”，点击“批量运行并采集”。范围为 1–10000 轮，单批最多 100000 个表格动作。启动前检查整批路径，包含后续轮次的相对位移累计。每轮从上一轮终点继续，不自动设零或返回起点；重复同一路径时，请在函数内安排回程和恢复接触高度。

每轮单独创建编号记录，必须等本轮所有分段保存成功后，才开始计算间隔并进入下一轮。重启/基线动作仍按原逻辑分段；metadata.context.batch 记录 id、round、count，CSV 仍为原 23 列。“本轮结束后停止”完成当前轮和保存后结束；间隔期间点击会直接结束。“中止”或空格立即停止后续动作并保留已有数据。控制器故障、零点失效、断流、串口错误或保存失败会中止整批，不能自动恢复继续。批量过程中禁止修改配置、目录、标签或手动移动。

## 自动恢复工作台

编辑内容约每 0.5 秒自动保存，关闭时再保存一次。下次启动恢复保存目录、布料名、X/Z 速度和加速度、脉冲/mm、方向映射、手动距离/模式、当前动作函数全部表格草稿（包括各行动作速度、加速度、备注和排序），以及批量次数/间隔。函数“保存/打开”仍用于导出和复用多套 JSON 流程。设置文件位于 `~/.config/xz-workbench/settings.json`，可用 XZ_WORKBENCH_SETTINGS 环境变量覆盖。

启动不会自动连接设备、执行动作、使能运动或恢复有效基线/坐标。方向键开关默认关闭；软件边界数值保留，但需重新确认零点和手动启用。保存目录不可用时明确提示，采集前必须重新选择，不会悄悄切换目录。损坏设置会提示，后续保存前将原设置保留为 `.invalid-…` 文件。

## 删除与回收站

“采集设置 → 管理记录 → 当前记录”支持 Ctrl/Shift 多选，点击“删除所选记录”并核对确认列表。整条记录（CSV、metadata、其他附属文件）移动到本保存目录的隐藏 `.workbench-trash/`，不改 CSV 内容；原名称立即释放。正在采集或后台保存的记录不能删除。未正常结束的历史记录在确认已无后台写入后也可以移入回收站。

“回收站”页选择记录后点击“恢复所选记录”。原名字空闲则原名恢复；已占用则分配同标签的新可用编号，同步更新 CSV 文件名和 metadata。回收站记录不会占用正常编号，也不会在当前记录列表中出现。此版本不提供永久清空回收站按钮。


## 人工机械标定与固定采集起点（2026-11-18）

本功能不需要原点开关，不会自动寻找实体原点。每次使用同一个定位块、刻线或量具进行人工对准，程序只能记录你的确认，重复定位精度取决于实际对准。**把上一轮停止处直接确认为原点，会改变现实坐标；请始终对准同一实体基准。**

首次使用：
1. 连接电机，核对脉冲/mm 与方向；打开“人工标定 / 固定采集起点…”，填写容易识别的固定基准名称。
2. 若需电动对位，点击“开始临时对位”并确认，回到手动页点击使能后用方向键/鼠标点动。临时对位只允许手动相对移动，不能运行自动函数、批量或绝对定位。
3. 对准实体基准并停止后，点击“已对准基准 · 确认机械原点”。确认会发送原固件 ZERO ALL，等待确认及新的两轴零坐标状态；不产生移动。此处定义固定机械坐标 (0,0)。
4. 手动使能后移动至采集起点，在标定窗口设置安全 Z，点击“将当前位置保存为起点”；也可填写机械坐标 X/Z 后点击“保存输入的起点”。保存起点不会移动或再次设零。
5. “移动到固定采集起点”会执行 Z 抬升 → X → Z 三段路线。Z 负向为上，指定安全 Z 必须小于或等于起点 Z；若当前位置 Z 更小（更高），保持更高位置再移 X。每段均检查启用的软件边界。安全高度由用户按实际机构确认，软件无法检测障碍。

后续启动：重新对准**同一实体基准**，保持同一个基准名并确认机械原点。之前保存的起点 X/Z、安全 Z 会恢复；不需要重新记录起点。然后使能并点击返回起点，或运行包含起点动作的函数。

动作表新增“到固定采集起点”，一次动作展开为上述三个运动段；该动作不使用轴、方向和距离输入框，速度/加速度可选全局或本行动作值。把它放在每轮开头即可让批量采集每轮从固定机械坐标开始。已有相对移动动作保留，用来表达从固定起点出发的扫描距离。批量启动前仍检查整批路径，不会自动插入回程。

标定有效性只存在本次连接内。重新启动/重连、改变任一轴脉冲换算、单轴重新设零、故障或运动中止导致零点失效后，都需重新确认。重设机械原点后，原软件边界会清空，需重新核对启用。起点绑定固定基准名称及 X/Z 脉冲换算；名称或换算变化后，旧起点不可调用，需要重新保存。旧 API ZERO ALL 作为人工确认的兼容入口，主界面使用显式确认窗口。

CSV 列及数据单位不变。metadata.context.coordinate_reference 记录 manual 方法、基准名称、标定 ID、确认时间和换算；valid 表示本次记录是否建立了人工机械参考。capture_start_mm 记录本次配置中的起点和安全 Z。没有标定的手动静态采集会明确记录 valid=false，不能把该坐标当成已标定世界位置。传感器 REBOOT 不改变电机机械参考，但仍需新基线。
